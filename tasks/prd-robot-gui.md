# PRD：Robot GUI 真机动作工作台

## 1. 概述

建设一个以真实 Unitree 机器人为中心的动作开发与调试工作台。Python FastAPI 后端负责机器人 SDK2/DDS 连接、状态汇聚和控制会话；React 前端提供实时关节状态、浏览器 3D 姿态展示、FSM 模式与基础行走控制、上半身手掰示教、动作文件管理和真机回放。

首版聚焦 G1 29DoF、17DoF 上半身动作工作流，并包含已支持 FSM 模式切换和键盘行走控制。行走与上半身动作仅在对应 G1 固件/SDK 组合已完成实机验证且运行时条件通过时允许并行。部署支持后端运行在机器人本机/PC2，或运行在同网段开发电脑；浏览器通过 WebSocket 接收状态、通过 API 请求控制。系统面向真机使用，不要求在真机操作前经过 MuJoCo/仿真验证流程。浏览器里的三维模型仅显示遥测姿态，不承担物理仿真或真机安全验收。

## 2. 目标

- 用户可在浏览器确认 G1 DDS、FSM、LowState 等关键连接/状态是否在线及数据新鲜度。
- 全量展示 29 个关节的角度、速度、估算力矩、温度、电压和状态，以及电池、IMU、运动模式信息。
- 支持双臂加腰 17DoF 的真机手掰录制、命名保存、浏览、删除、导入和导出。
- 支持选择动作并真机回放：从当前实测姿态平滑进入动作，完成后返回回放前姿态并交还控制权。
- 支持切换当前 G1 SDK/固件明确支持的 FSM 模式，并提供带速度上限的键盘行走控制。
- 仅在当前 G1 固件/SDK 组合已完成实机验证且运行时条件通过时，允许行走与 17DoF 上半身动作并行。
- 支持语音播报连接状态及录制/回放结果；首版不接受语音控制指令。
- 复用当前 `group` + `frames` 动作 JSON，允许已有动作直接导入使用。
- 以 Python 为服务端技术栈，并支持机器人端和同网段电脑两种部署位置。
- 采用分期路线：首版专注 G1 动作工作流；后续扩展 R1 与综合机器人能力。

## 3. 用户故事

### US-001：连接 G1 并查看连接状态
**描述：** 作为机器人操作员，我希望选择部署网卡并看到 SDK2/DDS 连接结果，以便知道工作台是否收到真实机器人数据。

**验收标准：**
- [ ] 后端支持配置 DDS 网卡，并可运行于机器人本机/PC2或同网段电脑。
- [ ] 页面明确显示连接状态、配置的网卡、最近一次数据时间和连接错误；未连接时显示原因而非伪造正常状态。
- [ ] 可运行部署必须使用真实 Unitree SDK2/DDS；未配置网卡、SDK 缺失或连接初始化失败时明确失败，不得启动或回退到 Mock/Fake 数据。
- [ ] 前端只接受 `mode=real` 的版本化快照；收到任何其他运行模式时拒绝数据并显示协议错误。
- [ ] 自动化测试可注入仅用于测试的遥测夹具；该夹具不得作为应用运行模式或用户演示路径暴露。
- [ ] 后端可通过配置关闭，不会因打开只读页面自动接管机器人。

### US-002：查看全量实时遥测与数据新鲜度
**描述：** 作为操作员，我希望查看全部关节、电池、IMU 和 FSM 实时状态，以便在示教或回放前了解机器人当前状态。

**验收标准：**
- [ ] 展示 29DoF 关节 `q/dq/ddq/tau_est`、温度、电压、模式及原始状态码，并展示 BMS、电池、髋部/躯干 IMU、FSM。
- [ ] 每个遥测源显示在线/延迟/离线及数据年龄；低频或失联状态不会显示为实时正常。
- [ ] 前端通过 WebSocket 消费后端快照，后端默认推送频率目标为 10Hz，可配置且限制最大频率。
- [ ] 遥测 JSON 使用有版本的 schema；关节按产品关节 schema 命名，不让前端维护第二套电机槽映射。

### US-003：在浏览器查看随真机更新的 3D 姿态
**描述：** 作为操作员，我希望看到网页中的机器人模型跟随实时关节和机身姿态更新，以便直观核对真实状态。

**验收标准：**
- [ ] 页面加载 Unitree 官方 G1 29DoF rev 1.0 URDF 及其本地 mesh 资源，并根据真实遥测关节角更新模型姿态。
- [ ] 仅当 LowState 的 `mode_machine` 与 rev 1.0 模型要求的 5 相符时报告模型兼容；不匹配或未知时明确提示且不得标记姿态 ready。
- [ ] 若遥测过期、模型不匹配或关节映射缺失，3D 区域显示明确状态，关节表仍可查看。
- [ ] 真机动作回放期间，3D 姿态持续跟随最新收到的真实关节遥测更新，展示实际反馈姿态而非仅展示回放目标轨迹；遥测过期时按数据新鲜度规则提示。
- [ ] 支持旋转、缩放和重置视角。
- [ ] 3D 显示为遥测可视化，不运行 MuJoCo，不将其描述为动力学仿真或安全证明。
- [ ] 在浏览器中验证 3D 模型、关节表和连接状态的联动。

### US-004：手掰录制 17DoF 上半身动作
**描述：** 作为动作设计者，我希望通过手动引导机器人双臂和腰部录制动作，以便快速获得真实机器人动作轨迹。

**验收标准：**
- [ ] 首版录制关节为双臂 14DoF + 腰部 3DoF；不允许录制腿部。
- [ ] 开始录制前显示一次真机控制确认；确认后显示接管/录制状态和已录制帧数。
- [ ] 录制样本来自真实 LowState，时间戳单调递增，保存动作以 `group: arms_waist` 和 `frames[{t,q}]` 表达，位置单位为 rad、时间单位为秒。
- [ ] 提供停止录制、命名保存和取消未保存录制操作；保存失败时明确报错并保留可恢复的录制状态。
- [ ] 取消或 DDS/反馈失效时停止继续使用陈旧反馈发命令，并进入明确的释放/故障状态。
- [ ] 手掰示教只提供受支持运行模式下的 17DoF 控制，不声称验证机器人动态平衡。

### US-005：管理动作文件
**描述：** 作为动作设计者，我希望浏览、导入、导出和删除动作，以便重复使用和整理录制结果。

**验收标准：**
- [ ] 动作列表显示名称、关节组、时长、帧数和来源；空列表有可操作提示。
- [ ] 可导入现有 `group` + `frames` JSON，并在导入时校验 JSON 结构、有限数值、维度和时间轴；错误文件显示具体原因。
- [ ] 可将动作导出为该兼容格式；删除动作前显示动作名并要求确认。
- [ ] 用户动作以兼容 JSON 文件保存在工作台配置的本地数据目录，不写入 PostgreSQL、安装包或参考仓库。
- [ ] 后端未配置的数据目录不可静默回退到安装目录；保存失败时明确报错并保留可恢复状态。
- [ ] 相同名称保存时要求明确覆盖确认，不能静默覆盖。

### US-006：明确确认并执行真机回放
**描述：** 作为操作员，我希望从动作列表选择动作、确认后回放并自动返回起始姿态，以便完成可控的真机动作流程。

**验收标准：**
- [ ] 每次真机回放前显示动作名、关节组、时长及明确的控制确认；取消确认不产生控制命令。
- [ ] 回放前读取当前真实姿态作为本次基线；从当前姿态平滑过渡到动作首帧，不先移动到离线默认姿态。
- [ ] 回放按动作帧时间播放，页面持续展示执行状态、当前帧/时间和最近反馈状态。
- [ ] 正常完成后平滑返回回放前的 17DoF 姿态并交还控制权。
- [ ] 用户停止、页面断连、LowState 过期、FSM/控制条件变化或 SDK 写入失败时，停止后续动作帧，并显示实际结果；不声称软件停止按钮等价于硬件急停。
- [ ] 首版不要求仿真、MuJoCo、碰撞规划或离线验收作为控制前置步骤；只保留必需的运行时输入/反馈有效性、控制模式和关节限位检查。

### US-007：按阶段扩展综合机器人能力与产品适配
**描述：** 作为系统维护者，我希望未来能增加 R1 和综合机器人模块，而不重写 G1 动作工作流。

**验收标准：**
- [ ] 首版运行时产品为 G1 29DoF；UI/API 不将 R1 标记为已支持。
- [ ] 架构将产品关节 schema、SDK 适配和能力可用状态隔离，未实现能力显示 unsupported/disabled，而不是假装可用。
- [ ] 首版仅开放当前 G1 SDK/固件明确支持且列入白名单的 FSM 模式；R1、导航、相机/点云、SLAM、语音识别/语音控制和 LLM 保持为后续阶段。
- [ ] 首版支持键盘行走控制；行走与上半身动作仅在对应固件/SDK 组合已完成实机验证且运行时条件通过时并行，否则拒绝并显示原因。

### US-008：查看和切换机器人 FSM 模式
**描述：** 作为机器人操作员，我希望查看当前 FSM 模式并切换到 G1 当前 SDK/固件支持的模式，以便从工作台管理机器人运行状态。

**验收标准：**
- [ ] 页面显示当前 FSM 模式及当前部署的 G1 SDK/固件明确支持且列入白名单的可切换模式；未支持或无法确认的模式不可操作。
- [ ] 切换模式前显示当前模式、目标模式并要求操作员确认；取消时不发送模式切换命令。
- [ ] 反馈过期、控制会话冲突、目标模式不支持或运行时条件不满足时拒绝切换，并显示具体原因。
- [ ] 模式切换后以真实 FSM 遥测确认结果；未收到确认时显示切换未确认，不伪报成功。
- [ ] 在浏览器中验证可切换、拒绝和等待遥测确认状态。

### US-009：使用键盘执行受限行走控制
**描述：** 作为机器人操作员，我希望在可行走模式下通过键盘和速度档控制 G1 移动，以便直接完成基础移动调试。

**验收标准：**
- [ ] 仅在已确认进入支持的行走模式并完成控制确认后，允许使用 WASD/方向键发送方向控制。
- [ ] 页面提供低/中/高三档速度；实际最大速度由后端配置限制，并在启动时校验配置值符合当前 SDK/固件约束。
- [ ] 按键释放、窗口失焦/隐藏、遥测过期、连接中断、模式退出或停止操作时，后端停止继续发送移动指令并发送零速度指令。
- [ ] 页面持续显示当前速度档、行走控制状态和停止状态；软件停止不得描述为物理急停。
- [ ] 行走与 17DoF 上半身动作仅对已完成对应 G1 固件/SDK 实机验证且运行时检查通过的组合开放；其他组合明确阻止并说明原因。
- [ ] 在浏览器中验证键盘输入、速度档切换、按键释放停止及失焦停止。

### US-010：播报连接、模式和动作执行状态
**描述：** 作为机器人操作员，我希望工作台能语音播报连接、模式切换、行走和录制/回放结果，以便在观察机器人时及时获知关键状态。

**验收标准：**
- [ ] 连接成功/断开、FSM 模式切换结果、行走控制启用/停止、录制开始/结束/保存失败，以及回放开始/完成/中止等关键事件有对应语音播报。
- [ ] 语音播报只读状态和结果，使用 TTS 合成文字，不播放自定义音频文件、不识别语音输入、不发送控制命令。
- [ ] 用户可关闭语音播报；播报不可用或失败时，页面仍显示对应文字状态并明确标识语音不可用。
- [ ] 连续遥测变化不会逐条触发语音播报。
- [ ] 在浏览器中验证语音开关、关键事件播报及不可用状态。

### US-011：端到端验证真机动作工作流
**描述：** 作为 QA 工程师，我希望用可重复的自动化测试覆盖连接、模式切换、行走控制、录制/存储和回放流程，以便发现跨 UI、API 和数据层的回归。

**验收标准：**
- [ ] 自动化 E2E 测试使用明确标记的 SDK/DDS 替身，覆盖连接状态、FSM 模式切换、速度档和键盘行走、17DoF 动作录制与保存、确认回放、回到起始姿态及交还状态；语音能力使用替身验证关键事件触发播报或不可用提示。
- [ ] 至少覆盖一个关键失败路径：过期反馈、拒绝确认、无效动作文件或模拟 SDK 写入失败，并断言 UI/API 报错且不继续发出后续帧。
- [ ] E2E 覆盖行走和上半身动作并行：已验证组合及运行时条件满足时允许；未验证或条件不满足时阻止并显示原因。
- [ ] 测试可在 CI 中运行，不连接真实机器人、不发送真实控制命令，并独立准备/清理测试数据。
- [ ] 实机验收作为受监督的人工现场步骤独立记录；自动化或 Mock 测试不得标注为实机验收。

## 4. 功能需求

- **FR-1：** 系统必须支持配置 DDS 网络接口，并通过 Unitree SDK2 Python 适配器连接 G1 状态数据。
- **FR-2：** 系统必须在只读遥测模式下订阅状态，而不自动获取关节控制权。
- **FR-3：** 系统必须把 DDS/LowState、BMS、IMU 和 FSM 数据归并到带时间戳的共享遥测快照。
- **FR-4：** 系统必须为每个遥测源计算并输出数据年龄与新鲜度状态。
- **FR-5：** 系统必须通过 FastAPI WebSocket 向 React 客户端推送版本化遥测快照。
- **FR-6：** 系统必须使用一个权威产品关节 schema 映射 SDK 电机槽、语义名称和 URDF 关节名。
- **FR-7：** 系统必须在页面展示 G1 所有关节状态以及电池、IMU、FSM 和 DDS 状态。
- **FR-8：** 系统必须在浏览器中用真实关节角和机身 IMU 姿态更新本地 Unitree 官方 G1 29DoF URDF 模型及其配套 mesh。
- **FR-9：** 可运行应用必须连接真实 Unitree SDK2/DDS；配置或初始化失败时显式失败且不得回退到 Mock/Fake，测试夹具仅用于隔离的自动化测试。
- **FR-10：** 系统必须支持 17DoF 双臂加腰的真实反馈手掰录制。
- **FR-11：** 系统必须使用单调时钟为录制帧生成时间，并保存为兼容动作 JSON 格式。
- **FR-12：** 系统必须支持动作文件导入、列举、导出、删除和显式覆盖确认。
- **FR-13：** 系统必须在真机示教、回放、FSM 模式切换和启用行走控制前要求操作员在 UI 确认本次控制操作。
- **FR-14：** 系统必须在回放前读取真实当前姿态，并以其作为进入动作和结束返回的基线。
- **FR-15：** 系统必须在正常回放结束后返回基线姿态并执行控制权交还流程。
- **FR-16：** 系统必须在反馈过期、控制模式不允许、动作输入无效或 SDK 发送失败时拒绝或中止对应真机控制，并明确报告原因。
- **FR-17：** 系统必须允许操作员请求停止/释放，并明确区分软件停止与物理急停。
- **FR-18：** 系统必须允许后端配置运行于机器人端或同网段电脑，并提供清楚的启动配置和部署说明。
- **FR-19：** 系统必须将 R1、导航、相机/点云、语音识别/语音控制和 LLM 保持为后续能力，首版状态标记为不支持。
- **FR-20：** 真机 Web 控制按用户选择暂不要求登录认证；部署说明必须明确该服务仅适合受信任局域网，禁止直接暴露到公网，并说明操作确认不等价于客户端身份认证。
- **FR-21：** 系统必须对连接状态、FSM 模式切换、行走控制及录制/回放关键结果提供可关闭的 TTS 语音播报，且不得将语音输入转换为机器人控制命令或播放自定义音频文件。
- **FR-22：** 系统必须显示当前 G1 SDK/固件支持并列入白名单的 FSM 模式，并允许操作员确认后切换到可用模式。
- **FR-23：** 系统必须支持在获准的行走模式下通过 WASD/方向键控制移动，并提供由后端配置上限约束的低/中/高速度档。
- **FR-24：** 系统必须在按键释放、窗口失焦/隐藏、遥测过期、连接中断、退出行走模式或停止操作时中止移动指令并发送零速度指令。
- **FR-25：** 系统必须仅对已完成当前 G1 固件/SDK 组合实机验证且运行时条件通过的行走与上半身动作并行组合开放控制，其他组合必须阻止并说明原因。

## 5. 非目标

- 首版不包含 MuJoCo 仿真、仿真验收关卡、碰撞规划或基于仿真的动作认证。
- 首版包含 G1 支持的 FSM 模式切换和键盘行走控制；不包含导航、SLAM、地图规划或未通过当前固件/SDK 实机验证的行走与上半身动作并行组合。
- 首版包含连接、FSM 模式切换、行走控制及录制/回放关键结果的 TTS 语音播报；不包含自定义音频文件播放、ASR、语音控制指令或 LLM。
- 首版不包含 R1 真机支持或通用多机型执行承诺。
- 首版不控制手指；手部模型为固定几何。
- 首版不包含全身 29DoF 示教或腿部动作回放。
- 首版不提供云端控制、互联网穿透或公网访问能力。
- 首版不把浏览器 3D 姿态显示称为物理仿真或动态平衡验证。

## 6. 设计考虑

- 页面划分为“实时状态”“动作库/示教”“动作回放”和“模式/行走控制”主要工作区，并始终显示连接/FSM/数据新鲜度状态。
- 真实控制操作需要一次明确确认；只读遥测页面无需确认，也不能隐式接管。
- 行走控制显示当前模式、速度档和控制状态；按键释放、页面失焦或遥测失效须由后端停止移动指令，不依赖浏览器继续发送停止消息。
- 示教和回放过程呈现明确的 Idle/Connecting/Recording/Playing/Returning/Releasing/Fault 状态，操作按钮按状态禁用。
- 语音播报仅覆盖关键状态转换和操作结果，不逐条播报高频遥测；语音不可用时以可见文字状态为准。
- 可参考 `references/UniRoboGui/docs/screenshots/robot-status.jpg` 的机器人状态布局、`references/UniRoboGui/docs/screenshots/joint-debug.jpg` 的关节调试布局，以及 `references/UniRoboGui/docs/screenshots/web-workstation.jpg` 和 `references/UniRoboGui/docs/screenshots/diagnostics.png` 的工作台/诊断信息组织；仅借鉴信息层级、状态呈现和 3D 区域，不复制首版范围外的导航、SLAM 和 LLM 功能。
- 遥测 3D 优先采用 Three.js + URDFLoader 的浏览器端可视化模式；MuJoCo 不作为界面或控制中间层。
- 参考实现分别保存在 `references/UniRoboGui` 与 `references/g1-action-studio`，只用于阅读，不作为新项目源码直接覆盖或隐式依赖。

## 7. 技术考虑

- 新项目根目录：`C:\Users\21537\Desktop\work\robot-gui`。
- Python 服务端：Python 3.11+、FastAPI、Uvicorn、Unitree SDK2 Python；DDS 生命周期由后端单一服务管理。
- Web 前端：React + TypeScript + Vite；WebSocket 用于只读遥测，HTTP API 用于控制请求和动作文件管理。
- 3D：Three.js 与 URDFLoader；使用 `unitreerobotics/unitree_ros` 的 G1 29DoF rev 1.0 官方 URDF 和配套 mesh，按其 BSD 3-Clause license 保留声明并本地部署，不依赖外部运行时下载。
- 动作存储：首版使用兼容的 JSON 文件与本地数据目录，不引入 PostgreSQL 或其他数据库作为动作存储。
- 语音播报实现方式：[Assumption] 优先使用浏览器 SpeechSynthesis 能力，不接入第三方云 TTS 服务。若浏览器不支持或语音合成不可用，页面须明确提示并保留文字状态。
- 后端应通过接口隔离 SDK、遥测快照、动作存储和控制会话；仅允许隔离的测试夹具用于自动化测试，不提供 Fake/Mock 应用运行模式。
- FSM 模式和速度指令必须通过 G1 SDK/固件支持白名单及后端速度上限校验；不允许前端直接绕过后端校验发送真机命令。
- 控制发送线程/任务、会话互斥、取消和资源清理需由后端统一管理；移动指令需有后端超时停止机制，浏览器断开不能留下无人管理的控制发送循环。
- 行走与上半身动作并行能力按固件/SDK 组合维护实机验证白名单；未验证组合默认不可并行，且运行时须重新检查反馈新鲜度、控制模式及会话状态。
- HTTP 服务面向局域网且按用户要求不实现登录；部署只能处于受信任网络，不允许公网暴露。操作确认只是误触防护，不是认证或访问控制。
- 用户明确要求不增加仿真验收步骤；必需的运行时反馈有效性、控制模式、数值与关节限位检查仍属于真机命令执行条件。

## 8. 分期路线与成功指标

### 首版（本 PRD 交付）
G1 连接/遥测、29DoF 状态页、网页 3D 实时姿态、FSM 模式切换、键盘行走控制、17DoF 手掰示教、动作文件管理、明确确认的真机回放与自动返回/释放，以及连接和动作结果 TTS 播报。行走与上半身动作仅对通过验证的组合开放并行。

### 后续阶段
1. 扩展经验证的 G1 行走与上半身动作并行组合。
2. 相机、点云、SLAM/导航等感知与移动能力。
3. 语音识别、语音控制和 LLM 等交互能力；首版仅提供关键状态 TTS 播报。
4. R1 产品适配；以实际产品能力和真机验证结果逐项开放。

### 成功指标
- 连接后 5 秒内页面显示首个真实遥测快照或明确连接失败原因。
- WebSocket 默认遥测推送频率为 10Hz；连续运行 10 分钟无未处理异常，数据年龄状态可正确反映断流。
- 对任一有效 17DoF 录制，保存后可在动作列表看到并重新加载；导出文件可由当前 G1 Action Studio 的动作加载器读取。
- 仅当前 G1 SDK/固件白名单内模式可供切换；键盘行走在低/中/高速度档均受配置上限约束，按键释放或页面失焦后停止移动命令。
- 行走与上半身动作并行仅对已实机验证且运行时条件满足的组合开放；其他组合被阻止并显示原因。
- 在支持语音合成的浏览器中，连接、模式切换、行走控制及录制/回放关键状态事件可触发 TTS 播报且可关闭；语音合成不可用时页面显示明确提示和对应文字状态，不播放自定义音频文件。
- 一次完整 E2E 测试可使用仅测试可用的注入式遥测/SDK 夹具走通模式切换、键盘行走、示教、存储、回放确认与返回释放；失败路径断言控制被停止且无额外动作帧。夹具不作为应用运行模式或用户演示路径。
- 真机执行必须由现场监督验收单独记录；E2E 通过不得替代这一记录。
